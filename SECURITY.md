# Security

Use the local edition only on a trusted computer. Never expose its HTTP port publicly. Saved jobs and exported files may contain private data even though API credentials are kept in memory.

Do not attach tokens, customer files, database exports, cookies, `.runtime/`, or signed attachment URLs to public issues. Use GitHub's **Security → Report a vulnerability** private reporting feature for a security issue. If unavailable, open a public issue containing only a request for a private reporting channel, without details or personal data.

Only the most recent tagged release is maintained. This is early software; use a small sample first and verify the resulting manifest before relying on an export.
